1决策重置

首版完整能力

Nav2 自己覆盖建图、定位、costmap、全局规划、局部控制、行为树、取消与恢复，因此 N1–N6 的第一版不再等待 FAST-LIVO2 或 EGO。

冻结输入

现有 Driver /ubuntu/loco/state JSON 转换为 Odometry/TF；/ubuntu/lidar/cloud 的 <point_step, point_count, raw points> envelope 重建 PointCloud2 并投影为 LaserScan。legacy payload 是首版正式输入。

增强不改契约

N6 基线通过后，FAST-LIVO2 只替换 odom source，EGO 只替换/对比 local controller。14-action 契约、nav_id 与安全边界不变。

方案一现在的定义：Nav2-only 先形成能建图、重启定位、规划和输出安全 shadow 的完整卡片；FAST-LIVO2/EGO 不是首版成功条件。

3Driver + navigation2 两卡架构

虚线框内属于 navigation2 Perception 卡片；左侧两个输出端口和下游可信执行端都由现有 Driver 卡负责。Agent Core 从画布三条精确连线发现执行关系，为一次导航任务分配 trusted nav_id，并以 Driver 的私有 start/info/stop 生命周期守住物理执行边界。

6首版成熟组件选型

SLAM Toolbox / AMCL

建图时由 SLAM Toolbox 产生 `/map` 与 `map→odom`；保存地图后切 Map Server + AMCL。模式切换比同时叠加两个 TF owner 更可验证。

NavFn

首版室内平地 occupancy grid 直接使用 NavFn，避免在 DDL 前同时调参 Smac 的多模型能力。跨房间全局路径已足够。

DWB Omni

DWB 在 Nav2 Humble 成熟可用，支持全向底盘采样。首版限速 `vx≤0.15 m/s`、`|vy|≤0.12 m/s`、`|wz|≤0.35 rad/s`，仅输出 shadow。

MVP 场景：室内平地二维 / 2.5D 导航。楼梯、明显崎岖地面、原生三维多楼层不在 08-06 开发冻结范围。

7Perception / Driver 与安全边界

Perception 拥有

  • `navigation2` 工具与 `controlled_spatial` 规范实现
  • Nav2 容器、地图/定位、规划、任务状态与 shadow
  • N1–N6 门禁、诊断、故障结果和验收证据

G1 Driver 拥有

  • Unitree DDS 与 MID360 / 机身状态的标准 topic 适配
  • 主运控、急停、姿态、租约、TTL 与有限时长高层运动
  • N5 后唯一物理 executor；不保存地图，只在有效租约内绑定 nav_id
红线：Perception 不导入 Unitree SDK，不直接调 SmartMotion，不把 Nav2/EGO 直连物理速度话题。Driver 永不订阅 raw shadow；最终画布只允许精确 1 个预期的 `loco` subscriber 订阅 structured proposal，实验 executor 必须在产品验收前移除。

9N6 之后的两个增强位

E1 · FAST-LIVO2 odom enhancement

仅在 Nav2-only 基线证明可导航后，将 native odom bridge 替换为 FAST-LIVO2 `Odometry + odom→base_link`。需用同场轨迹对比漂移、抖动、CPU/内存与重定位效果，可随时退回 native source。

E2 · EGO-Planner controller enhancement

先作为 DWB 的独立 comparator，消费同一 local subgoal/odom/obstacles，输出不可执行的独立 shadow。只有安全性、成功率和资源占用全部更优时才讨论替换 DWB。
